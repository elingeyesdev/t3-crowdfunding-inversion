Historias de usuario y criterios de aceptación

Historias organizadas por rol para describir qué necesita cada persona, dónde realiza la acción y cómo comprobar el resultado. Cada criterio utiliza Dado / Cuando / Entonces y tiene un identificador propio.

80 historias55 actuales8 parciales17 pendientes304 criterios

Cómo interpretar esta especificación

  • Actual: el recorrido tiene controles web conectados. Los criterios describen el comportamiento que debe comprobarse; no equivalen a una certificación de pruebas realizadas.
  • Parcial: existe un recorrido utilizable, con una limitación indicada expresamente. Sus criterios actuales no dan por cumplida la mejora pendiente.
  • Pendiente: no hay un recorrido web operativo o completo. Sus criterios son objetivos propuestos; las decisiones abiertas se indican antes de su aceptación.
  • El alcance incluye la web de escritorio. Se usan los nombres visibles de sus menús. No se incluyen funcionalidades exclusivas de la aplicación móvil.
  • Los aportes y aumentos de capital utilizan saldo simulado. No se especifica una pasarela de pagos reales.
  • Google y el asistente IA no están disponibles. Se documentan únicamente en el bloque de pendientes, sin presentarlos como alternativas de acceso o soporte actuales.
  • Las historias actuales se basan en los recorridos documentados y en sus condiciones de aplicación. Una capacidad interna sin pantalla conectada se considera pendiente.

Condiciones para verificar los criterios

Utiliza una cuenta del rol indicado y datos preparados para el escenario: campañas con el estado requerido, solicitudes KYC pendientes, aportes, recompensas o movimientos de auditoría según corresponda. Una lista vacía no demuestra el recorrido de aprobación o revisión. Las operaciones de cierre, eliminación, suspensión y revocación cambian los datos: usa registros destinados a pruebas.

Las notificaciones de nuevos eventos se comprueban con las preferencias correspondientes habilitadas. Los escenarios que requieren un tercero usan otra cuenta autorizada. No se incluyen credenciales personales ni contraseñas en este documento.
